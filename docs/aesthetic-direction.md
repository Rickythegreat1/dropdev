# Aesthetic Direction

## Target Feel

DevDrop should feel calm, spatial, tactile, trust-centered, evidence-first, and
precise. It should have the energy of a flight-check control surface: quiet,
inspectable, and serious about what is known before movement.

## Hard Bans

- default shadcn sameness
- fake glassmorphism
- meaningless metric cards
- vague status pills
- purple/blue "AI app" gradients
- random sparkles
- generic SaaS dashboards
- over-rounded everything
- noisy severity colors
- decorative visuals that do not explain workspace state

## Visual Language

- Use physical object metaphors only when they clarify state: plates, rails,
  tracks, topology lines, receipts, diff surfaces, and approval walls.
- Favor restrained earth, graphite, brass, green-gray, and paper tones.
- Use square or lightly rounded geometry. Avoid bubbly controls.
- Show machine topology as inspectable spatial relationships, not as decorative
  network art.
- Use severity color sparingly. Prefer precise labels and evidence lists.
- Let blocked actions look unavailable and explained, not dramatic.

## Copy Direction

- Say what is known, what is missing, and what is blocked.
- Avoid hype, magical automation claims, and generic "AI-powered" language.
- Use non-panicky safety language.
